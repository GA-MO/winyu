## สามทางเชื่อมต่อ

| ทาง | ใช้กับ | งานต่อหนึ่งระบบ | สถานะ |
|---|---|---|---|
| [ประตูตัวเลข](/docs/connect/metrics) | KPI บนแดชบอร์ดและคำถามเรื่องตัวเลข | adapter หนึ่งตัวต่อคลังข้อมูลหนึ่งแห่ง | สัญญาพร้อม · เขียน adapter |
| [REST connector](/docs/connect/rest) | ระบบที่มี API เช่น HR, CRM, ITSM | config หนึ่งไฟล์ | พร้อมใช้ · เดโม CRM |
| [MCP connector](/docs/connect/mcp) | ระบบที่มี MCP server | config หนึ่งไฟล์ | พร้อมใช้ · เดโม LMS |

ดูโค้ดครบทุกแบบได้ที่ [ตัวอย่างการเชื่อมต่อ](/docs/connect/examples)

## เลือกทางไหน

<Steps>
<Step>

### เป็นตัวเลขหรือ KPI ใช่ไหม

ใช้ประตูตัวเลขเสมอ แม้คลังข้อมูลจะมี MCP ก็ตาม เพราะการ์ดต้องการ query ที่ตายตัวและนิยาม metric ชุดเดียวกันทั้งแชทและแดชบอร์ด MCP หรือ REST เป็นได้แค่ช่องทางรับส่งข้างใน adapter

</Step>
<Step>

### ระบบมี MCP server ไหม

ถ้ามี ใช้ MCP connector เขียน config หนึ่งไฟล์ Winyu อ่านรายการ tool และ schema จาก server เอง

</Step>
<Step>

### ระบบมี REST API ไหม

ใช้ REST connector ถ้าองค์กรมี API gateway ให้ต่อผ่าน gateway ที่เดียว ไม่ต่อตรงทีละระบบ

</Step>
<Step>

### ไม่มี API เลย

อ่านจากสำเนาในคลังข้อมูลผ่านประตูตัวเลข ไม่ต่อฐานข้อมูลของระบบงาน (OLTP) โดยตรง

</Step>
</Steps>

## ทุกทางผ่านกลไกเดียวกัน

ไม่ว่าจะต่อด้วยทางไหน ทุกการเรียกผ่านขั้นตอนเดียวกัน

1. ตรวจว่าบทบาทนี้ใช้ tool นี้ได้ และ admin ไม่ได้ปิดไว้
2. ใส่ขอบเขตของผู้ถามลงใน argument หรือ query
3. เรียกระบบต้นทางในนามผู้ถาม
4. กรองแถวที่อยู่นอกขอบเขต
5. ปิดบังฟิลด์ตามบทบาท
6. ตัดเหลือไม่เกิน 60 แถว และกั้นผลลัพธ์ไว้เป็นข้อมูล ไม่ใช่คำสั่ง
7. บันทึก audit พร้อมรหัสบอกว่าเกิดอะไรขึ้น เช่น `SCOPE_TRIMMED` เมื่อ Winyu ตัดแถวนอกขอบเขตทิ้ง หรือ `NONE_IN_SCOPE` เมื่อไม่มีข้อมูลในขอบเขตของผู้ถาม

งานที่เหลือต่อระบบจึงเป็นการกำหนดสิทธิ์ ซึ่งเป็นการตัดสินใจทางธุรกิจ ไม่ใช่งานเชื่อมต่อ
