## ตัวอย่าง

connector ของระบบอบรมที่ใช้ในเดโม

```ts
export const lmsConnector = defineMcpConnector({
  id: "lms",
  labelTh: "LMS (MCP)",
  sourceSystemTh: "ระบบอบรมผ่าน MCP",
  transport: { type: "http", url: env.LMS_MCP_URL },
  auth: (access) => signedIdentityHeaders(access, env.LMS_SECRET),
  timeoutMs: 4000,
  tools: {
    training_history: {
      labelTh: "ดูประวัติการอบรม",
      tier: "read",
      roles: "all",
      scope: [
        { kind: "inject", args: (access) => (access.regions === "all" ? {} : { regions: access.regions.join(",") }) },
        { kind: "filter", rows: onlyPeopleInView },
      ],
      sensitive: [{ field: "score", labelTh: "คะแนนสอบ", full: ["ceo", "hr_manager"], masked: ["sales_director", "sales_rsm"] }],
    },
  },
});
```

tool นี้ขึ้นบนระบบเป็นชื่อ `lms__training_history` และขึ้นในตารางสิทธิ์ของหน้า admin ทันทีที่เพิ่ม connector ลงในรายการ `CONFIGURED` ของ `lib/server/connectors/index.ts` ดูตัวอย่างอื่นได้ที่[ตัวอย่างการเชื่อมต่อ](/docs/connect/examples)

## ค่าใน config

| ค่า | ความหมาย |
|---|---|
| `id` | ชื่อ connector ใช้เป็นคำนำหน้าชื่อ tool |
| `transport` | `{ type: "http", url }` หรือ `{ type: "stdio", command, args }` สำหรับ server ที่รันเป็นโปรเซสบนเครื่องเดียวกัน |
| `auth(access)` | header ที่ส่งไปพร้อมทุกคำขอ สร้างจากตัวตนของผู้ถาม `access` เป็น `null` เมื่อ Winyu เรียกเอง เช่น ตอนอ่านรายการ tool |
| `timeoutMs` | เวลารอสูงสุด |
| `tools` | tool ที่เปิดใช้ ประกาศทีละตัว ไม่มีการเปิดทั้งหมด |
| `tools.*.roles` | บทบาทที่ใช้ได้ admin ปรับต่อได้ในหน้าสิทธิ์ |
| `tools.*.tier` | `read` หรือระดับที่ต้องขออนุมัติ ถ้าไม่ระบุ Winyu ถือว่าเป็นการกระทำที่ต้องอนุมัติก่อน |
| `tools.*.scope` | บังคับทุก tool ไม่มีค่าเริ่มต้น ถ้าไม่ระบุ ระบบไม่ยอมสร้าง connector |
| `tools.*.sensitive` | ฟิลด์ที่บางบทบาทเห็นเต็ม บางบทบาทเห็นเป็น `***` |
| `tools.*.output` | adapter แปลงผลดิบเป็นแถวของ Winyu ถ้าไม่ระบุ Winyu ย่อผลให้เอง |
| `tools.*.description` | ถ้าไม่ระบุ ใช้คำอธิบายจาก server (กั้นไว้เป็นข้อมูล) ควรเขียนเองเมื่อคำอธิบายของ server ไม่บอกว่าไม่ใช้กับคำถามแบบไหน |
| `tools.*.input` | ถ้าไม่ระบุ ใช้ schema จาก server |
| `tools.*.as` | ชื่อที่ใช้บน Winyu แทนชื่อของ server เช่น `search_handbook` เป็น `policy__handbook` |

## การบังคับขอบเขต

- `{ kind: "none", reason }` สำหรับข้อมูลที่ไม่ผูกกับคนหรือภาค เช่น นโยบายบริษัท ต้องเขียนเหตุผล
- `{ kind: "inject", args }` Winyu เขียนทับ argument ที่ระบุขอบเขตก่อนส่ง ต่อให้ AI ส่ง `regions: "all"` มา ก็ถูกเขียนทับด้วยภาคของผู้ถาม
- `{ kind: "filter", rows }` Winyu กรองแถวหลังได้ผล ถ้าถูกกรองทิ้งทั้งหมด ผู้ใช้ได้คำตอบว่าอยู่นอกขอบเขตสิทธิ์

ใช้ `inject` กับ `filter` คู่กันได้ และควรใช้คู่กันเมื่อระบบต้นทางกรองได้ไม่ละเอียดพอ

## ตัวตนของผู้ถาม

Winyu เปิด client แยกต่อผู้ใช้ (อายุ 10 นาที) และส่ง header จาก `auth(access)` ทุกคำขอ ในเดโม header ถูกลงลายเซ็นด้วย HMAC ถ้าลายเซ็นไม่ถูก server ตอบ 401 ในระบบจริงให้ใช้ token แบบ on-behalf-of จาก SSO แทน

## เมื่อระบบต้นทางมีปัญหา

| สถานการณ์ | ผลลัพธ์ |
|---|---|
| server ไม่ตอบหรือเกินเวลา | `CONNECTOR_UNAVAILABLE` ผู้ใช้เห็นว่าระบบไม่ตอบในขณะนี้ |
| server ตอบว่าผิดพลาด | `CONNECTOR_FAILED` ข้อความจาก server ถูกกั้นไว้เป็นข้อมูล |
| admin ปิด tool หรือปิดบทบาท | `TOOL_NOT_ALLOWED` พร้อม audit `deny` |
| server มี tool ที่ config ไม่ได้ประกาศ | เรียกไม่ได้ Winyu log ไว้ตอนเริ่ม server |

## ความปลอดภัยของคำอธิบาย tool

คำอธิบาย tool ที่ server ส่งมาและผลลัพธ์ทุกชุดถูกกั้นไว้เป็นข้อมูลก่อนถึง AI คำสั่งที่แฝงมาในข้อความของ server จึงไม่ถูกทำตาม
