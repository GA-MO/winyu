## สิทธิ์อยู่ในโค้ด ไม่อยู่ใน prompt

Winyu กรองรายการ tool ตามบทบาทก่อนที่ AI จะเห็น และใส่ขอบเขตภาคและแบรนด์ลงในทุก query ก่อนส่งออก prompt ไม่มี logic เรื่องสิทธิ์เลย ต่อให้มีคนสั่งในแชทให้ดูข้อมูลภาคอื่น คำขอนั้นก็ไม่ออกไปถึงระบบต้นทาง

## AI ไม่แต่งตัวเลข

AI เลือกว่าจะถาม metric ไหน แต่ไม่ได้เขียนตัวเลขเอง การ์ดผูกกับผลลัพธ์ของ tool โดยตรง และ Winyu เป็นผู้วาดการ์ด ตัวเลขทุกตัวจึงมาจากระบบต้นทางและมีที่มากำกับ

## ข้อมูลที่ไม่ใช่คำสั่ง

ผลลัพธ์จาก tool ข้อความจากผู้ใช้คนอื่น และความจำของ Winyu ถูกกั้นไว้เป็นข้อมูลก่อนถึง AI ข้อความที่แฝงคำสั่งมาในข้อมูลจึงไม่ถูกทำตาม

## ปิดบังและซ่อน

- **ฟิลด์อ่อนไหว**: กำหนดต่อบทบาทว่าเห็นเต็ม เห็นเป็น `***` หรือไม่เห็นเลย admin ปรับได้
- **กลุ่มเล็ก**: ตัวเลขที่รวมจากเอเย่นต์หรือพนักงานน้อยกว่า 3 รายถูกซ่อน เพื่อไม่ให้ย้อนกลับไปหาตัวบุคคลได้

## ควบคุมจากหน้า admin

- เปิดหรือปิด tool ต่อบทบาท
- ปิดทั้ง connector ในคลิกเดียว tool และปุ่มที่เกี่ยวข้องหายพร้อมกัน
- มีผลกับคำถามถัดไปทันที ไม่ต้องรีสตาร์ท

## Audit

ทุกการเรียกถูกบันทึก ได้แก่ ใครขอ tool อะไร ผ่าน connector ไหน ผลคือได้ ถูกปิดบัง หรือถูกปฏิเสธ และเพราะอะไร กรองดูตาม connector ได้

## ทดสอบแบบผู้โจมตี

ชุด red-team test ของ connector ทำงานกับ server จริงในโปรเซส

| กรณี | ผล |
|---|---|
| พนักงานขายทุกคนถามประวัติพนักงาน 40 คน | รั่ว 0 แถว |
| AI ส่ง `regions: "all"` | ถูกเขียนทับด้วยภาคของผู้ถาม |
| เพื่อนร่วมภาคที่อยู่นอกสายบังคับบัญชา | ถูกปฏิเสธ |
| ผู้จัดการภาคดูคะแนนสอบ | เห็นเป็น `***` |
| คำขอที่ไม่มีลายเซ็นตัวตน | server ตอบ 401 |
| tool ที่ server มีแต่ config ไม่ได้ประกาศ | เรียกไม่ได้ |
| admin ปิด tool ให้พนักงานขาย | ถูกปฏิเสธ พร้อม audit |
