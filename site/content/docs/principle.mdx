## อ่านสด ไม่ sync

การ์ดบนแดชบอร์ดเก็บเพียง "คำถาม" ไม่เก็บ "คำตอบ" การ์ดแต่ละใบถือ `MetricQuery` เช่น

```ts
{
  title: "ยอดขายรายภาค",
  kind: "bar",
  query: { metric: "net_sales_volume", dims: ["region"], range: { from: "2026-09-01", to: "2026-09-24" }, grain: "month", compare: "prev_period", limit: 12 },
}
```

ทุกครั้งที่เปิดแดชบอร์ด Winyu ส่ง query ของทุกการ์ดออกไปพร้อมตัวตนของผู้ใช้ ระบบต้นทางคำนวณแล้วส่งแถวกลับมา Winyu จึงไม่มีสำเนาข้อมูลที่ต้อง sync หรือที่อาจล้าสมัย

## สิ่งที่ Winyu เก็บเอง

| เก็บ | ตัวอย่าง |
|---|---|
| หน้าตาแดชบอร์ด | การ์ดไหนปักหมุด ลำดับ ประวัติเวอร์ชันสำหรับย้อนกลับ |
| การแจ้งเตือน | ความผิดปกติที่พบ สถานะการติดตาม |
| งานที่ส่งต่อ | คำขอ บริบท และการตอบกลับระหว่างคน |
| [ความจำส่วนตัว](/docs/memory) | คำที่ผู้ใช้เรียกบ่อย เรื่องที่สนใจ |
| Audit | ใครเรียกอะไร ได้ ถูกปิดบัง หรือถูกปฏิเสธ |

## ทุกการ์ดบอกที่มา

ผลลัพธ์ทุกชุดมี `provenance` ติดมาด้วย ได้แก่ ระบบต้นทาง เวลาของข้อมูล ขอบเขตที่ใส่ และฟิลด์ที่ถูกปิดบัง การ์ดแสดงข้อมูลนี้ใต้ตัวเลขเสมอ ผู้ใช้จึงรู้ว่าตัวเลขมาจากไหนและเป็นข้อมูล ณ เวลาใด

<Callout title="ในเดโม">
ตอนนี้ระบบต้นทางทุกระบบเป็นตัวสร้างข้อมูลสมมติที่ให้ผลเหมือนเดิมทุกครั้ง ตัวสร้างนี้ใช้สัญญาเดียวกับระบบจริง การเปลี่ยนไปใช้ระบบจริงจึงไม่ต้องแก้หน้าจอหรือ logic ของ Winyu
</Callout>
