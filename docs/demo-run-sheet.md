# Run sheet: เดโม Winyu แบบหลายจอ

เรื่องเดียว 4 คน: ยอดขายเข้าภาคอีสานจะหลุดเป้า CEO ส่งเรื่องให้ผู้จัดการขายภาค ผู้จัดการภาคส่งต่อให้พนักงานขาย พนักงานขายรับ แล้วฝ่ายไอทีเห็นว่าใครส่งอะไรให้ใครและใครอนุมัติ ทุกขั้นที่กดบนการ์ดไม่เรียกโมเดลเลย

ขั้นส่ง ส่งต่อ รับ และหน้า Audit ลองผ่าน HTTP ด้วย session จริงแล้วเมื่อ 16 ต.ค. 2569 เวลาในเอกสารนี้มาจากรอบนั้น ส่วนเรื่องที่ Winyu สืบให้ต้องเรียกโมเดลตอนเช้า ถ้อยคำของเรื่องจึงต่างไปได้ในแต่ละวัน

## เช้าวันงาน (ประมาณ 10 นาที)

1. หยุด server ก่อน แล้วคืนข้อมูลให้สะอาด

   ```bash
   bun run seed
   ```

   คำสั่งนี้ลบทุกไฟล์ JSON ใน `.data` รวมถึงแชตเก่าและ connector ที่เพิ่มจากหน้า admin ถ้ายังต้องใช้ connector ให้สำรอง `.data/connectors.json` และ `.data/secrets.json` ไว้ก่อน seed ไม่ได้ส่งเรื่องให้ใครไว้ก่อน เรื่องแรกบนเวทีจึงเป็นเรื่องที่ CEO ส่งเอง

2. สั่ง Winyu สืบให้ 4 คน (ประมาณ 7 calls ต่อคน ใช้เวลา 2 ถึง 4 นาที)

   ```bash
   bun run investigate -- --users=u_thana,u_anucha,u_krit,u_ton --save
   ```

3. เปิด server โดยปิดงานเบื้องหลัง

   ```bash
   WINYU_SCHEDULER=off bun run dev
   ```

   หน้าแรกของ CEO ต้องขึ้นป้าย "Winyu สืบให้แล้ว · N เรื่องด่วน" ถ้าขึ้นว่า "Winyu ยังไม่ได้สืบให้วันนี้ การ์ดที่ปักไว้อยู่ด้านล่าง" แปลว่าข้อ 2 ยังไม่เสร็จหรือไม่สำเร็จ

`bun run call-tool` ใช้ส่งงานล่วงหน้าแทนการกดบนจอไม่ได้แล้ว เครื่องมือที่เขียนข้อมูลต้องมีการกดอนุมัติจากคนนั้นบันทึกไว้ก่อน ถ้าลองสั่ง ระบบจะตอบ `NOT_APPROVED` และไม่ส่งอะไรออกไป

## จัดจอ

เปิด 4 หน้าต่างใน Chrome ตัวเดียว แต่ละหน้าต่างใช้ที่อยู่ของตัวเอง แล้วลากให้แคบเท่าจอมือถือ

| หน้าต่าง | ที่อยู่ | กดการ์ด "เริ่มเดโมที่นี่" ใบที่ | เข้าเป็น |
|---|---|---|---|
| 1 | `http://ceo.localhost:3100` | ขั้นที่ 1 | คุณธนา ประธานเจ้าหน้าที่บริหาร |
| 2 | `http://rsm.localhost:3100` | ขั้นที่ 2 | คุณอนุชา ผู้จัดการขายภาค ภาคอีสาน |
| 3 | `http://rep.localhost:3100` | ขั้นที่ 3 | คุณกฤต พนักงานขาย ขอนแก่น |
| 4 | `http://it.localhost:3100` | ขั้นที่ 4 | คุณต้น ผู้ดูแลระบบไอที (เข้าแล้วไปที่ Admin console ทันที) |

แต่ละที่อยู่เก็บการเข้าระบบของตัวเองใน cookie แยกกัน ถ้าทุกหน้าต่างใช้ `localhost:3100` เหมือนกัน คนที่เข้าล่าสุดจะทับทุกหน้าต่าง เข้าครบแล้วกด reload ทุกหน้าต่างหนึ่งครั้งเพื่อเช็กว่ายังเป็นคนเดิม

ปุ่ม "N" มุมซ้ายล่างคือเครื่องมือของ Next ในโหมด dev กดแล้วเลือกซ่อนได้

## ลำดับบนเวที

### 1. CEO ส่งเรื่อง (หน้าต่าง 1, ประมาณ 30 วินาที)

1. กดป้าย **Winyu สืบให้แล้ว · N เรื่องด่วน** ใต้คำทักทาย
2. กดเรื่องภาคอีสาน (ป้าย "ด่วน") เรื่องจะกางออกพร้อมการ์ดหลักฐาน
3. กด **ส่งต่อ** ใต้การ์ด ชีต "ส่งต่อการ์ดนี้" เปิดขึ้น
4. เช็กในชีต: เลือก **ต้องตอบ** อยู่แล้ว, ผู้รับคือ คุณอนุชา พรหมศรี ติ๊กไว้แล้วในกลุ่ม "ผู้รับผิดชอบเรื่องนี้", ช่อง "ขออะไร" เป็นหัวเรื่องที่ Winyu สืบได้, "ต้องการเมื่อไร" ตั้งเป็น "วันนี้" ให้กด **ด่วน**
5. กด **ส่ง** แผง "ส่งต่อแล้ว" ขึ้นทันที (ฝั่ง server ใช้ 0.02 วินาที)

พูด: "Winyu สืบให้ตั้งแต่เช้า ผมแค่ตรวจแล้วกดส่ง ไม่ต้องพิมพ์ ไม่ต้องรอ AI"

### 2. ผู้จัดการขายภาคส่งต่อ (หน้าต่าง 2, ประมาณ 30 วินาที)

1. ไม่ต้องคลิกอะไร กระดิ่งขึ้นเลข 1 เองภายในประมาณ 10 วินาทีขณะที่หน้าต่างเปิดอยู่
2. กดกระดิ่ง รายการบนสุดคือ "คุณธนา วงศ์สกุล ขอให้คุณตอบ: (สิ่งที่ CEO ขอ)" กด **เปิดดู**
3. หน้าเรื่องแสดงการ์ดเดียวกันตามสิทธิ์ของผู้จัดการภาค สิ่งที่ขอ และ "เส้นทางของเรื่อง"
4. กด **ส่งต่อ** แล้วเลือก คุณกฤต จันทร์เสน (คนแรกในทีมของคุณ) แล้วกด **ส่งต่อ** อีกครั้ง

พูด: "การ์ดเดียวกัน แต่ผู้จัดการภาคเห็นเฉพาะส่วนในภาคตัวเอง และไม่ต้องเล่าเรื่องใหม่ให้ลูกทีมฟัง"

### 3. พนักงานขายรับเรื่อง (หน้าต่าง 3, ประมาณ 15 วินาที)

1. กระดิ่งขึ้นเอง กดกระดิ่ง แล้วกด **เปิดดู** ที่เรื่องจากคุณอนุชา
2. กด **รับ**

พูด: "ทุกคนในสายเห็นสถานะเดียวกัน ไม่ต้องโทรตาม"

### 4. CEO เห็นเส้นทาง (หน้าต่าง 1, ประมาณ 10 วินาที)

1. กระดิ่งของ CEO ขึ้น "คุณกฤต จันทร์เสน รับเรื่อง …" และ "คุณอนุชา พรหมศรี ส่งต่อเรื่อง … ให้ คุณกฤต จันทร์เสน"
2. กดรายการใดก็ได้ หน้าเรื่องแสดง "เส้นทางของเรื่อง": คุณธนา ผู้ส่ง → คุณอนุชา ส่งต่อแล้ว → คุณกฤต รับแล้ว

พูด: "CEO รู้ว่างานไปถึงใครแล้ว โดยไม่ต้องถามสักคน"

### 5. ฝ่ายไอทีเห็นทุกขั้น (หน้าต่าง 4, ประมาณ 20 วินาที)

1. ใน Admin console กดแท็บ **Audit**
2. กดชิป **การส่งงานและการแก้ไข** (ถ้าอยากเปิดตรง ใช้ `http://it.localhost:3100/admin?tab=audit&kind=activity`)
3. แผง "ใครส่งงานอะไรให้ใคร" แสดงใหม่สุดก่อน: คุณกฤต รับเรื่อง, คุณอนุชา ส่งต่อ → คุณกฤต, คุณธนา ส่งเรื่อง → คุณอนุชา แต่ละแถวมีชื่อการ์ด เวลา และ "กดเองบนการ์ด"

พูด: "ไอทีเห็นว่าใครส่งอะไรให้ใคร เมื่อไร และใครอนุมัติ แต่ไม่เห็นข้อความที่แต่ละคนพิมพ์"

ถ้ามีเวลา ให้กดชิปเดิมซ้ำเพื่อกลับไปดูการเรียกเครื่องมือทั้งหมด หรือกลับไปแท็บ "ภาพรวม" แล้วกดคำแนะนำ "ใครส่งงาน ส่งต่อ หรือรับเรื่องอะไรบ้างใน 7 วันล่าสุด" ให้ Winyu ตอบเป็นการ์ด (1 ถึง 2 calls ราว 15 ถึง 30 วินาที)

## ทางเลือก: CEO สั่งในแชต

ใช้เมื่ออยากโชว์ว่าพิมพ์สั่งได้ ช้ากว่าการกด **ส่งต่อ** เพราะต้องรอโมเดล

1. หลังเปิดเรื่องภาคอีสาน กด **ถามต่อ** แล้วพิมพ์ **ส่งเรื่องนี้ให้ผู้จัดการขายภาคอีสาน ด่วน** แล้วกดปุ่มส่ง (บนจอมือถือ Enter คือขึ้นบรรทัดใหม่)
2. Winyu ตอบด้วยการ์ดอนุมัติ "ส่งการ์ดให้ คุณอนุชา พรหมศรี" พร้อมสิ่งที่ขอ ความด่วน และผู้รับ
3. กด **ส่ง** (หรือ **ยังไม่ส่ง** ถ้าจะยกเลิก) จากนั้นทำขั้น 2 ถึง 5 ตามเดิม ในหน้า Audit แถวของ CEO จะเป็น "คุณธนา วงศ์สกุล ยืนยันในแชต" แทน "กดเองบนการ์ด"

ขั้นนี้ยังไม่ได้ลองกับโมเดลจริงในรอบ 16 ต.ค. ส่วนที่ตรวจแล้วคือการ์ดอนุมัติไม่ส่งอะไรออกไปจนกว่าจะกด และ Audit แสดงการส่งจากแชตเพียงครั้งเดียว (ทดสอบในโค้ด)

## ถ้าเกิดเหตุ

| อาการ | ทำอะไร |
|---|---|
| หน้าแรก CEO ขึ้น "Winyu ยังไม่ได้สืบให้วันนี้" | รัน `bun run investigate` ตามข้อ 2 ของช่วงเช้าแล้ว reload ถ้าไม่ทัน ให้ใช้ทางเลือกในแชต |
| กระดิ่งไม่ขยับเกิน 10 วินาที | กระดิ่งดึงข้อมูลใหม่เฉพาะตอนหน้าต่างมองเห็นอยู่ คลิกที่หน้าต่างนั้นหนึ่งครั้ง หรือกด reload |
| การ์ดอนุมัติในแชตขึ้นว่า "ไม่ได้ส่งการ์ด" | ถ้าพิมพ์ข้อความใหม่ตอนที่การ์ดอนุมัติยังรออยู่ ระบบนับว่าไม่อนุมัติ การ์ดนั้นจึงไม่ส่ง ให้สั่งส่งใหม่อีกครั้งแล้วกด **ส่ง** ก่อนพิมพ์อย่างอื่น |
| หน้าต่างกลายเป็นคนอื่น | ดูที่อยู่ ทุกหน้าต่างต้องใช้ที่อยู่ของตัวเองตามตาราง ถ้าเปิด `localhost:3100` เปล่า ๆ การเข้าระบบจะทับกัน |
| ชีตส่งต่อไม่ได้ติ๊กคุณอนุชาไว้ | พิมพ์ "อนุชา" ในช่องค้นหาแล้วติ๊กเอง |
| พนักงานขายเห็นเรื่องในกระดิ่งมากกว่า 1 เรื่อง | มาจากการซ้อมรอบก่อน ให้ `bun run seed` ก่อนขึ้นเวที |
| แผง Audit ว่าง | ดูว่าช่วงเวลาเป็น "7 days" และไม่ได้เลือกผู้ใช้ไว้ แล้วกด "Clear" |

## ค่าใช้จ่ายต่อรอบ

การสืบตอนเช้าประมาณ 28 calls ไม่ถึง $0.2 สำหรับ 4 คน (ตัวเลขจากการซ้อม 16 ต.ค.) ขั้น 1 ถึง 5 แบบกดบนการ์ดไม่เรียกโมเดลเลย (รอบลองผ่าน HTTP ไม่มี `.data/model-calls.json` เกิดขึ้น) ทางเลือกในแชตเรียกโมเดลทั้งตอน **ถามต่อ** และตอนสั่งส่ง (รอบนี้ไม่ได้วัด) ซ้อมกี่รอบก็ได้ แต่ควร `bun run seed` และสั่งสืบใหม่ก่อนขึ้นเวทีจริง

## ลิงก์ demo สาธารณะ (GKE)

ลิงก์สาธารณะมีที่อยู่เดียว จึงใช้วิธี `*.localhost` ไม่ได้ ถ้าต้องเล่นหลายจอบนลิงก์นั้น ให้เปิดแต่ละคนใน Chrome profile แยกกัน หรือใช้มือถือจริงคนละเครื่อง
