# Cop pilot — วัดว่าคนใช้จริงก่อนขยาย

ตัวเลขทั้งหมดอ่านได้จาก `/admin` → แท็บการใช้งาน → "ใช้จริงไหม" (`lib/server/adoption.ts`)

## กลุ่ม pilot (6 สัปดาห์)

บทบาทที่มีงานประจำวันที่ Cop ช่วยได้จริง ไม่ใช่บทบาทที่ถามนาน ๆ ครั้ง:
- ผู้จัดการขายภาค (RSM) — ความผิดปกติของเอเย่นต์, ส่งต่อให้ trade marketing
- พนักงานขาย — รายการเยี่ยมวันนี้
- วางแผนซัพพลาย — สต๊อกต่ำกว่าเกณฑ์, เฝ้าดู DC

## สิ่งที่วัดทุกสัปดาห์

| ตัวชี้วัด | อ่านจาก | ทำไม |
|---|---|---|
| ผู้ใช้ที่กลับมาใน 7 วัน / ทั้งกลุ่ม | ผู้ใช้ที่กลับมาใช้ใน 7 วัน แยกตามบทบาท | คนไม่กลับมา = ไม่มีค่าพอ |
| ความผิดปกติที่ถูกเปิดหรือจัดการ (%) | ความผิดปกติถูกทำอะไรบ้าง | ต่ำ = alert ยังเป็น noise หรือไม่เกี่ยวกับคนที่เห็น |
| งานส่งต่อที่ปิดได้ และเวลากลางถึงการตอบกลับครั้งแรก | งานที่ส่งต่อ | handoff ช่วยให้งานเดินจริงไหม |
| การ์ดที่ปักแล้วถูกดูใน 14 วัน | การ์ดแดชบอร์ด | การ์ดที่ไม่มีใครดูคือต้นทุนที่ไม่ได้อะไร |
| เรื่องที่เฝ้าดูและจำนวนครั้งที่แจ้ง | งานที่ Cop ทำเอง | ผู้ใช้ให้ Cop ทำงานแทนหรือยังต้องมาถามเอง |

## เกณฑ์หยุด (ตัดสินที่สัปดาห์ที่ 4)

หยุดขยายไปกลุ่มอื่น และแก้หรือตัดฟีเจอร์ก่อน ถ้าข้อใดข้อหนึ่งเป็นจริง:
- ผู้ใช้ที่กลับมาใน 7 วัน < 50% ของกลุ่ม pilot
- ความผิดปกติที่ถูกเปิดหรือจัดการ < 30%
- งานส่งต่อที่ปิดได้ < 40% หรือเวลากลางถึงการตอบกลับ > 24 ชม.

การ์ดที่ถูกดู < 30% ไม่ใช่เกณฑ์หยุด แต่เป็นสัญญาณให้ลดการ์ดตั้งต้นของบทบาทนั้น

## สิ่งที่ยังวัดไม่ได้

- เวลาจากความผิดปกติถึงการกระทำแรก: เวลาของ alert เป็นปฏิทินข้อมูล (`TODAY`) ไม่ใช่นาฬิกาจริง ต้องเก็บเวลาที่ระบบพบครั้งแรกแยกก่อนจึงวัดได้
- ผลต่อธุรกิจ (สต๊อกขาดลดลง, ยอดที่กู้คืน): ต้องใช้ข้อมูลจริงหลัง pilot
