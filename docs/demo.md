# Winyu — สคริปต์เดโม

ข้อมูลทุกตัวเลขมาจาก generator ที่ seed คงที่ (`mulberry32(20260922)`) วันที่ปัจจุบันของระบบคือ **22 กันยายน 2026** รันด้วยโมเดล `mock` ได้ทั้งหมดโดยไม่ต้องมี API key — ทุกฉากเรียก tool จริง ตัวเลขบนการ์ดจึงเป็นตัวเลขจริงของชุดข้อมูล

## เตรียมก่อนเดโม

```bash
bun install
bun run seed          # ล้าง .data (thread, memory, packet, layout) ให้เริ่มจากศูนย์
bun run dev           # http://localhost:3100
```

เปิด `http://localhost:3100` → ระบบพาไป `/login` เลือก **บทบาท** ก่อน (10 บทบาท แต่ละใบบอกว่าเห็นอะไร ขอบเขตภาค และจำนวนเมตริกตามสิทธิ์ปัจจุบัน) แล้วเลือก **คน** ในบทบาทนั้น ไม่ต้องใส่รหัสผ่าน ผู้ดูแลระบบไอทีเข้าที่ Admin console ทันที คนอื่นเข้าหน้าแรก สลับคนได้จากแผงบัญชี ซึ่งจัดกลุ่มตามบทบาทเช่นกัน
สลับบุคคลระหว่างเดโมได้จากรูปโปรไฟล์มุมขวาบน → "สลับผู้ใช้"

ถ้ายังไม่มีความผิดปกติหรือพยากรณ์ ให้เข้าสู่ระบบเป็น **คุณต้น (IT)** แล้วเรียก `POST /api/jobs/run` หนึ่งครั้ง (หรือพิมพ์ในแชทว่า "รันงานเบื้องหลังทั้งหมด") ระบบจะรันเองอยู่แล้วเมื่อ `.data/alerts.json` ยังไม่มี

## ฉากที่ 1 — ผู้จัดการขายภาคอีสานตามยอดที่ตก (≈4 นาที)

**เข้าสู่ระบบเป็น: คุณอนุชา พรหมศรี (`u_anucha`) ผู้จัดการขายภาค ภาคอีสาน**

| ขั้น | ทำอะไร | ควรเห็นอะไร |
|---|---|---|
| 1 | ดูหน้าแรก | คำทักทาย + สรุปเช้านี้หนึ่งประโยค (ความผิดปกติที่เจอเมื่อคืน + งานที่รออยู่) การ์ดแดชบอร์ดเบลออยู่ด้านหลัง ชิปคำถามที่ถามบ่อย 4–6 อัน |
| 2 | พิมพ์ `ยอดขายเดือนนี้เทียบเป้าแยกตามภาค` | ตอบสั้น 1 ประโยค + การ์ด Metric สามใบและกราฟแท่งแนวนอน **เห็นเฉพาะภาคอีสาน** เพราะ scope ถูกฉีดเข้า query อัตโนมัติ (บรรทัดล่างการ์ดบอกแหล่งข้อมูลและวันที่) |
| 3 | พิมพ์ `เอเย่นต์รายไหนยอดตกบ้าง top 10` | ตารางเอเย่นต์พร้อมส่วนต่างเทียบงวดก่อน — "ส.รุ่งเรือง เทรดดิ้ง" −10.2% (anomaly #1) และสองรายที่หยุดสั่งของ "อีสานรุ่งโรจน์ ค้าส่ง" / "อุบลศรีสุข เทรดดิ้ง" ราว −36% (anomaly #4) |
| 4 | พิมพ์ `เทียบยอดขายเข้ากับยอดขายออกของเอเย่นต์` | กราฟสองชุดซ้อนกัน ขายเข้าต่ำกว่าขายออก = ของค้างที่เอเย่นต์ ไม่ใช่ผู้บริโภคหยุดซื้อ |
| 5 | พิมพ์ `มีอะไรผิดปกติบ้างวันนี้` | การ์ด Alert เรียงตามความรุนแรง แต่ละใบมีสมมติฐาน 1 ข้อ + วิธีตรวจ 2 ทาง |
| 6 | พิมพ์ `ส่งต่องานให้ผู้รับผิดชอบ` | ระบบหา owner จาก RACI (คุณพิม เทรดมาร์เก็ตติ้งอีสาน) แล้วขึ้น **การ์ดอนุมัติ** — กด "อนุมัติ" จึงจะสร้างงานจริง |
| 7 | กดกระดิ่งมุมขวาบน | ลิ้นชักกล่องงาน: งานที่เพิ่งส่งอยู่ในแท็บ "ส่งแล้ว" |

**ประเด็นที่ต้องพูด:** ตัวเลขทุกตัวมาจาก tool ไม่ใช่ความจำของโมเดล · ขอบเขตข้อมูลบังคับที่ชั้น query ไม่ใช่ที่ prompt · งานที่ส่งต่อพกแค่ "คำถาม" ไม่ได้พกตัวเลข

## ฉากที่ 2 — การตลาดเจอยอดพุ่ง แล้วส่งให้ซัพพลาย (≈4 นาที)

**เข้าสู่ระบบเป็น: คุณเบญ เตชะวงศ์ (`u_ben`) ผู้จัดการแบรนด์ กลุ่มนอนแอลกอฮอล์**

| ขั้น | ทำอะไร | ควรเห็นอะไร |
|---|---|---|
| 1 | พิมพ์ `ปุระขายดีผิดปกติที่ไหน` | การ์ด Alert ของ Purra PET 600 ที่เชียงใหม่/ลำพูน ขายออกสูงกว่าที่คาดอย่างมีนัยสำคัญ (anomaly #2) พร้อมวิธีตรวจสองทาง |
| 2 | พิมพ์ `สต๊อกปุระพอขายอีกกี่วัน` | ตารางวันครอบคลุมสต๊อกรายศูนย์กระจายสินค้าเฉพาะแบรนด์ปุระ + แถบเตือนสีแดง: ลำพูน ≈7.9 วัน ต่ำกว่าเกณฑ์ 10 วัน (anomaly #3) |
| 3 | พิมพ์ `พยากรณ์ยอดขาย 8 สัปดาห์ข้างหน้า` | กราฟเส้นพร้อมขอบบน/ขอบล่าง และ MAPE ในคำอธิบายการ์ด |
| 4 | พิมพ์ `ส่งต่องานให้ผู้รับผิดชอบ` → อนุมัติ | งานถูกส่งพร้อมหลักฐาน (query ที่เพิ่งรัน ไม่ใช่ค่าที่เห็น) |
| 5 | **สลับผู้ใช้เป็น คุณวีร์ เจริญสุข (`u_wee`) นักวางแผนซัพพลาย** | กระดิ่งมีตัวเลขแจ้งเตือน |
| 6 | เปิดกล่องงาน → การ์ดงานที่ได้รับ | หลักฐานถูก **รันใหม่ตามสิทธิ์ของคุณวีร์** ฟิลด์ที่เขาไม่มีสิทธิ์จะขึ้นว่า "ถูกปิดตาม policy" พร้อมปุ่มขอสิทธิ์ |
| 7 | กด "เปิดในเอเจนต์ของฉัน" | เปิดแชทใหม่ที่เอเจนต์ดึงข้อมูลให้เองแล้ว จบด้วย **ทางเลือกสองทาง** (ย้ายสต๊อกใน 3 วัน / เพิ่มรอบผลิตสัปดาห์หน้า) พร้อมข้อเสนอแนะ |
| 8 | กด "รับงาน" หรือ "ขอข้อมูลเพิ่ม" | สถานะเปลี่ยน ผู้ส่งได้รับแจ้งเตือนกลับ และแชทเดิมของผู้ส่งมีข้อความระบบเชื่อมไปยังคำตอบ |

**ประเด็นที่ต้องพูด:** แพ็กเกจงานไม่ทำข้อมูลรั่วข้ามแผนก เพราะผู้รับรัน query เองใต้สิทธิ์ตัวเอง (D5) · การตรวจจับเป็นดีเทอร์มินิสติก โมเดลแค่อธิบายและเสนอ (D4)

## ฉากที่ 3 — ซีอีโอเตรียมประชุมบอร์ด และไอทีตรวจธรรมาภิบาล (≈4 นาที)

**เข้าสู่ระบบเป็น: คุณธนา วงศ์สกุล (`u_thana`) ประธานเจ้าหน้าที่บริหาร**

| ขั้น | ทำอะไร | ควรเห็นอะไร |
|---|---|---|
| 1 | พิมพ์ `ยอดขายเดือนนี้เทียบเป้าแยกตามภาค` | คราวนี้เห็นครบ **ทุกภาค** — คำถามเดียวกัน บทบาทต่างกัน ผลต่างกัน |
| 2 | พิมพ์ `เทียบปีที่แล้วเป็นอย่างไร` | กราฟสองเส้น ปีนี้เทียบปีก่อนรายเดือน |
| 3 | พิมพ์ `เตรียมประชุมบอร์ด` | Metric มูลค่าขายรายกลุ่มธุรกิจเทียบปีก่อน + ตารางกำไรขั้นต้น |
| 4 | ถามซ้ำคำถามเดิมอีกครั้ง | เอเจนต์เสนอปุ่ม "ปักเป็นการ์ดบนแดชบอร์ด" (ผ่านการ์ดอนุมัติ) |
| 5 | กด ⌘D หรือ "ดูแดชบอร์ด" | การ์ดที่ปักไว้ชัดขึ้นมาด้านหน้า ถาดการ์ดที่ระบบเสนอมีเหตุผลกำกับ ("คุณถามคำถามนี้ 6 ครั้งใน 14 วัน") |
| 6 | **สลับผู้ใช้เป็น คุณต้น อรุณรัตน์ (`u_ton`) ผู้ดูแลระบบไอที** → เปิด `/admin` จากเมนูโปรไฟล์ | คอนโซลเรียบ ๆ 5 แท็บ |
| 7 | แท็บ "ผู้ใช้และสิทธิ์" | ตารางสิทธิ์ metric ต่อบทบาท: ● เห็นทั้งหมด / ◐ ปิดบางส่วน / ○ ไม่เห็น |
| 8 | แท็บ "เครื่องมือ" → กดปิด `create_handoff` | kill switch มีผลทันทีกับทุกบทบาท (กดกลับเป็น "ใช้งานได้" ก่อนจบเดโม) |
| 9 | แท็บ "Audit" | ทุกการเรียก tool ถูกบันทึก: ใคร ทำอะไร ผลลัพธ์ กี่แถว กี่มิลลิวินาที กรองตามผู้ใช้/เครื่องมือ/ผลลัพธ์ได้ |
| 10 | แท็บ "การใช้งาน" | คำถามต่อวัน 14 วันล่าสุด คำถามที่พบบ่อย คำถามที่ระบบยังตอบไม่ได้ และค่าใช้จ่ายโดยประมาณ |
| 11 | แท็บ "จำลองมุมมอง" → เลือก คุณอนุชา + เมตริก "เงินเดือนเฉลี่ย" | เห็นผลลัพธ์จริงที่เขาจะได้: ค่าทั้งหมดเป็น `***` พร้อมบรรทัด "ปิด 3 ฟิลด์ตามสิทธิ์" |

**ประเด็นที่ต้องพูด:** `bun test tests/red-team.test.ts` ยิงคำถามข้ามขอบเขต 60+ แบบต่อทุกบทบาท แล้วยืนยันว่าไม่มีตัวเลขรั่วสักตัว รวมถึงกฎ min-cell (แถวที่รวมเอเย่นต์น้อยกว่า 3 ราย ถูกปิด)

## ฉากที่ 4 — ข้อมูลที่มีแต่บริษัทเบียร์ (≈3 นาที)

**เข้าสู่ระบบเป็น: คุณอนุชา พรหมศรี (`u_anucha`) แล้วสลับเป็น คุณวีร์ เจริญสุข (`u_wee`)**

| ขั้น | ทำอะไร | ควรเห็นอะไร |
|---|---|---|
| 1 | คุณอนุชา พิมพ์ `ส่วนแบ่งตลาดเทียบคู่แข่ง` | ส่วนแบ่งตลาดเบียร์ของเรารายจังหวัดในภาคอีสาน เดือน ส.ค. (retail audit เดือนที่ครบล่าสุด) เทียบปีก่อน นครราชสีมาเสียมากสุด (57.7%, −10.4%) |
| 2 | หน้าแรก → การ์ดแจ้งเตือน P1 นครราชสีมา → ตรวจสอบ | "คาราบาวได้ส่วนแบ่งเพิ่ม 4.1 จุด ในช่วงเดียวกับที่ของเราลดลง 3.5 จุด" ช่องว่างบนการ์ดเป็น "จุด" |
| 3 | พิมพ์ `เทียบส่วนแบ่งตลาดของทุกผู้ผลิตในนครราชสีมา เทียบปีก่อน` | บุญรอด / ไทยเบฟ / คาราบาว / รายอื่น — คาราบาว 13.1% |
| 4 | พิมพ์ `ดูยอดขายออกเบียร์ของเราในนครราชสีมาเทียบปีก่อน` | ยอดของเรายังโต +7.9% — เสียส่วนแบ่งเพราะตลาดโตเร็วกว่า ไม่ใช่ขายได้น้อยลง |
| 5 | สลับเป็นคุณวีร์ พิมพ์ `เดือนหน้ามีวันไหนที่กระทบยอดขาย` | Timeline: วันออกพรรษา 26 ต.ค. 2569 ห้ามขายเครื่องดื่มแอลกอฮอล์ — ครั้งก่อนขายออกเบียร์ −90% เอเย่นต์สั่งเข้า 2 วันก่อนหน้า +29% (วัดจากข้อมูลในขอบเขตของผู้ถาม) |

**ประเด็นที่ต้องพูด:** ปี 2569 เป็นปีอธิกมาส เข้าพรรษา 30 ก.ค. – ออกพรรษา 26 ต.ค. · ระบบตรวจความผิดปกติรู้จักวันห้ามขายและช่วงพรรษา จึงไม่ปลุกผู้จัดการเพราะวันพระ · คุณเมย์ (HR) ถามปฏิทินได้แต่ไม่เห็นผลกระทบ เพราะไม่มีสิทธิ์ดูยอดขาย

## คำถามสำรองระหว่างเดโม

โมเดล `mock` ตอบคำถามเหล่านี้ได้ (ดูรายการเต็มใน `lib/server/mock-script.ts`):

```
ยอดขายเดือนนี้เทียบเป้าแยกตามภาค
ยอดขายภาคอีสานเทียบเป้า
เอเย่นต์รายไหนยอดตกบ้าง top 10
เทียบปีที่แล้วเป็นอย่างไร
เทียบยอดขายเข้ากับยอดขายออกของเอเย่นต์
มีอะไรผิดปกติบ้างวันนี้
ปุระขายดีผิดปกติที่ไหน
สต๊อกปุระพอขายอีกกี่วัน
พยากรณ์ยอดขาย 8 สัปดาห์ข้างหน้า
เตรียมประชุมบอร์ด
เงินเดือนเฉลี่ยแต่ละฝ่าย
ส่งต่องานให้ผู้รับผิดชอบ
ส่วนแบ่งตลาดเทียบคู่แข่ง
เดือนหน้ามีวันไหนที่กระทบยอดขาย
```

ถ้าตั้ง `ANTHROPIC_API_KEY` ใน `.env.local` ตัวเลือกโมเดลจะมี Claude Sonnet 5 เป็นค่าเริ่มต้นและถามนอกสคริปต์ได้อิสระ เครื่องมือและสิทธิ์เหมือนกันทุกประการ

## ถ้ามีอะไรพลาดระหว่างเดโม

| อาการ | ทำอย่างไร |
|---|---|
| โมเดลตอบว่าไม่มีสคริปต์ | คำถามไม่ตรง regex ใด — ใช้คำถามสำรองด้านบน หรือสลับไปโมเดลจริง |
| ไม่มีความผิดปกติ/พยากรณ์ | เข้าเป็นคุณต้นแล้วสั่ง "รันงานเบื้องหลังทั้งหมด" (tool `run_job`) |
| อยากเริ่มใหม่หมด | `bun run seed` แล้วรีเฟรช (ข้อมูลธุรกิจไม่หาย เพราะสร้างจาก generator ไม่ได้เก็บใน `.data`) |
